# openKylin / UKUI desktop port — inventory and implementation mapping

Status (2026-10-31, after the root review): five source-backed packages on the merged engine (root `905c059` + the mode-aware window-style contract), pinned sources, palette
mapping, a shared asset-pack catalogue, wallpaper fragment for the root catalogue, registration notes (no patch), native evidence and tests. What each area does and does not claim is in
"What is claimed" below; what shared code must provide is in [integration-contract.md](integration-contract.md). Palette mapping: [palette.md](palette.md). Native evidence:
[native/README.md](native/README.md).

## What "openKylin" is here

`https://github.com/openkylin` holds 3,923 repositories. Almost all are Debian-source mirrors. The **desktop** is
**UKUI** (Kylin's Qt/QML desktop). The GitHub organisation is a **read-only mirror last pushed in April 2025**; UKUI
development itself continues on gitee.com/openkylin, which is outside the task's entry point, so this port is pinned to
what the GitHub mirror holds. Release branches are named after rivers: `yangtze` (1.0) < `nile` (2.0) < `huanghe`
(newest). Every pin below prefers `openkylin/huanghe`, then `nile`, then the Debian/upstream branch.

Local blobless clones: `~/.cache/decebal-upstreams/openkylin/<repo>` (not committed). Exact commits, commit dates, the
licences each repository declares in `debian/copyright`, and git tree OIDs of the asset directories we depend on are in
[`assets/desktop-ports/openkylin/sources.json`](../../../assets/desktop-ports/openkylin/sources.json), generated by
`assets/desktop-ports/openkylin/tools/pin_sources.py`.

## Panels (from `ukui-panel`)

`Shell` picks `Version4` unless `currentPanelVersion` says otherwise, so the **classic taskbar is the default**; the
island panel (`Version5`) is a switchable second mode. Both are real.

| mode | QML container | geometry from source |
|---|---|---|
| Classic taskbar `org.ukui.panel` | `panel/qml/org.ukui.panel/ui/Container.qml`, `panel/src/view/panel.cpp` | docks to **all four edges**, drag to move, size policies Small 48 / Medium 72 / Large 92 (default 48, min 48, max 92), margins 0, padding 0, radius 0, `appViewSpacing` 8·ratio, `configSpacing` 4·ratio, ratio = clamp(size/48, 1, 2); app view (start, search, separator, task manager, task view) at the leading edge, config view (tray, calendar, show-desktop) at the trailing edge; tray area capped to 38.2 % of the panel length |
| Island taskbar `org.ukui.panelNext` | `.../org.ukui.panelNext/ui/MainContainer.qml`, `panel/src/view/panel-next.cpp` | **bottom only**, default height 56 (min 48, max 80), margins L/R/B 8, T 0, padding 2, centred, auto-fits its islands; island gap 8·ratio, island vertical margin 4·ratio, ratio = clamp(h/56, 0.85, 1.43); islands are rounded `kRadiusWindow`·ratio with a 1 px border of button-text colour at 25 % alpha |
| Top bar `org.ukui.panelTopBar` | `panel-top-bar.cpp` | top edge, 32 px, can host the data and settings islands |

Island contents (defaults written by `panel-next.cpp`, order data → app → settings): **data island** = menu starter,
IDM (intelligent data manager), task view (min width 64, max 208); **app island** = task manager, search; **settings
island** = system tray, calendar (min width 192). App-island padding is 12·ratio, item gap 4·ratio. Plugin ids:
`org.ukui.menu.starter`, `.panel.search`, `.panel.taskView`, `.panel.taskManager`, `.panel.separator`,
`.panel.calendar`, `.panel.showDesktop`, `.panel.idm`, `.systemTray`.

### Mapping onto the shared panel framework (`docs/universal-panels.md`)

| UKUI | Decebal key | Notes |
|---|---|---|
| start button (menu starter) | `launcher` | `[branding]` logo = the openKylin start icon (see assets) |
| search | `search` | |
| task manager | `tasks` | |
| task view | — | no registry key; nearest is `layout`/overview, **not** claimed. Gap. |
| separator | — | renderer-internal |
| system tray (+ its volume/network/battery/bluetooth items) | `tray`, `volume`, `network`, `bluetooth`, `battery`, `notifications` | UKUI hosts these inside its tray; Decebal lists them as applets |
| calendar | `clock` | date + time, opens a calendar |
| show desktop | `show_desktop` | |
| IDM | — | no equivalent. Gap. |

* Classic mode → `[dock] style = "windows"`, `position = "bottom"`, `[bar] enabled = "auto"`. The taskbar already
  draws on all four edges.
* Island mode → `[bar] style = "dux"`, `background = "islands"`, `position = "bottom"`, three groups
  (`left` = data island, `center` = app island, `right` = settings island), `margin = 8`, `spacing = 8`, `radius = 12`,
  `[dock] enabled = false`. **Renderer requirement:** UKUI centres the three islands as one cluster sized to its
  content; the Dux `islands` profile spreads start/centre/end across the band. The package selects the closest shipped
  behaviour; the cluster-centred variant is reported to root as an integration request (see below), not faked.

## Window decoration

**Correction (earlier revisions of this document said UKUI has no decoration plugin in the mirror and used the Control Center's header):** the real UKUI decoration is the
KDecoration plugin `src/plugins/kdecorations/ukui` of **`openkylin/kwin`** (branch `openkylin/nile`, commit `01bf914`, LGPL-3 plugin licence), which I had skipped because
`ukui-kwin` is only the older KWin rename. Measured from `ukui-decoration.cpp`: header (`m_borderTop`) **38 px** (tablet 64 / modal 48), buttons **30 × 30 px** (24 px in
right-to-left), button top margin 4 px, button spacing 4 px, window radius **12 px** (`RADIUS`; read from the global theme's `window-radius`, so 0 in Classic), borders 0 with a
resize-only margin. The 40 px / 30 px header I first reported belongs to `ukui-control-center`'s own client-drawn title widget, not to the window decoration.

The decorations owner's rdwm already ships this as the measured style pair `openkylin` / `openkylin-dark` (38 px, 30 px plates, radius 12, red close). The packages use the
generic **mode-aware window-style contract** (`decoration.style_light/style_dark`, fallbacks `adwaita-light` / `adwaita`, native geometry; Classic overrides only `radius = 0`),
which applies the pair **only if the running window manager lists it** and otherwise uses the proven fallback with a persistent warning. Proof against real builds:
[native/decoration-proof.json](native/decoration-proof.json) (`tests/e2e/openkylin-decoration-proof.py`): 8 applies (2 packages × 2 modes × new/old rdwm). New rdwm (24 styles):
`openkylin` in light, `openkylin-dark` in dark, no record. Old rdwm (15 styles, no pair): `adwaita-light` / `adwaita`, apply exit 0, record `decoration_compat` naming the
wanted pair. Not proven here: a pixel capture of the native frame on a mapped client window (the decorations owner owns that).

## Fonts

UKUI tokens specify `Noto Sans CJK SC`. The port requests `Noto Sans` / `Noto Sans CJK SC` from the user's fonts and
does not bundle a font (OFL fonts are installable separately; none are required to render).

## Cursors and icons: independent selection

The packages declare *suggested* icon and cursor packs through asset recipes
(`assets/desktop-ports/openkylin/asset-packs.toml`, installed by the shared installer). Icons and cursors remain separately selectable in Settings whatever
the theme suggests; choosing a theme never forces them.

## Honest remaining gaps

* **Island panel:** Dux spreads groups to the edges instead of one centred, content-sized cluster, and the list validator rejects registry keys (contract §5, §5b).
* **Launcher and Control Center/sidebar:** native geometry from the Gitee sources, with the gaps listed in [replica-gaps.md](replica-gaps.md) (no full-screen mode, user/computer/expand actions, notification column, blur material, animations).
* **Taskbar:** Classic's plate corner clamps at 2 px (UKUI: 0); the 32 px icon size is declared but not pixel-measured; the search control is UKUI's square icon button (generic `[taskbar] search = "button"`); the task-view, separator and AI-assistant widgets have no applet, and the search icon is the shell's magnifier, not the pack's `kylin-search`.
* **Window decoration:** the native frame on a mapped client window is the decorations owner's to capture; engines without the window-style contract reject these packages (needs the lingmo lane's commits).
* The greeter is not replicated (out of scope); no task-view or IDM applet.
* Classic's 70 %-wash highlight is replaced by the solid brand colour for accents (documented in palette.md).
* `kylin-startmenu` is bundled (one 128 px PNG per package, the pack the package suggests; pinned blob ids in each ATTRIBUTION.md, verified by the test), so the start button is the real mark with or without an icon pack; the user's icon pack still decides every other icon.
* Cursors: DMZ-White has no CSS-name aliases (the catalogue format has no alias hook for prebuilt packs); the icon packs' `from moka` provenance is **unresolved** (not researched, not assumed); the licence blobs (`debian/copyright`) are pinned with `license_oids`, so the install reports them verified (a GitHub archive itself is not byte-stable, so no `archive_sha256`).
* No broad green claim: two unit tests failed in an earlier private scratch merge with and without these packages (historical, see `registration-notes.md`).
* X11 only; Wayland not exercised. The wallpaper candidates' authorship and licence are unverified; nothing is bundled.
